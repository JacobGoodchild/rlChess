## Status (end of session 5)

### Engine (`src/RlChess.Engine`)
- 64-square board with pre-computed tables; pseudo-legal generation + legality filter with a
  shortcut (not in check, unpinned non-king, not en passant → legal without make/undo). Zobrist
  hashing, FEN in/out (rejects impossible positions), SAN + UCI, `Game` (moves, SAN, result, PGN
  export, `recordSan: false` for speed), `Pgn.Parse/ParseAll`, `Position.ToAscii()`.
- Perft matches all standard positions; ~50M positions/sec (`Arena -- perft 6`).
- `ChessClock` + `TimeControl` (increments, pause/resume via `Stop`/`Start`, injectable time
  source for tests) and `TimeoutRules` (flag → loss, or draw if the opponent can't ever mate;
  a simplified version of lichess's rule, see the XML docs).
- End reasons now include Timeout, TimeoutVsInsufficientMaterial, Agreement, ThinkTimeExceeded.
- `IPlayer`, `IAsyncPlayer` (cancellable; should return best-so-far when cancelled),
  `RandomPlayer`, `MatchRunner`.

### Players (`src/RlChess.Players`)
- `PlayerRegistry.Entry(Id, DisplayName, Description, Category, Create(level), Levels?)`.
  Categories: Random / Computer (search) / AI (learned). `LevelRange(min, max, default)`;
  levels are clamped. `TryParse("id:level")` is shared by the Arena.
- Only `random` exists. The owner writes minimax and RL players himself: **don't write any**.

### Arena (`src/RlChess.Arena`)
- `--games --p1 id[:level] --p2 id[:level] --pgn --fen --max-plies --seed --threads`, `perft`.
  Prints results, draw reasons, average length, speed, Elo difference ± 95% margin.

### Website (`src/RlChess.Web`)
- `Pages/Home.razor(.cs)`: one page. Each colour has a seat (person or bot). `ScheduleNext()`
  decides what happens after any change (bot move / premove / wait). `_generation` + `_cts` cancel
  stale bot work on new game, undo, pause, resign, time-out.
- Modes: vs computer, two players, computer vs computer (pause, slow/normal/fast).
- New-game dialog (`Components/NewGameDialog.razor`, `PlayerPicker.razor`): grouped players
  with "none yet", level slider for players with levels, colour, clock presets + custom.
  Choices remembered (`Game/GameSetup.cs`, a small key=value string in localStorage).
- Think-time limit (settings menu, default 10 s) for games without a clock. Async players are
  cancelled at the limit and get 1 s to return a move; sync players are checked afterwards. Over the
  limit → the bot loses ("Think-time limit exceeded"). With a clock, the clock is the limit.
- Clocks start after the first move of the game. The bot's cosmetic pre-move pause doesn't use
  its clock. No undo in clock games. `ClockDisplay` re-renders itself every 100 ms; `WatchFlags`
  in Home detects flag falls.
- Premoves (vs computer only), several can be queued: movement-pattern destinations
  (`Game/Premoves.cs`, like lichess), computed on a "virtual" board with the queue applied
  (`VirtualBoard`), which is what the board shows meanwhile. One is played per turn, auto-queen on
  promotion; the first illegal one drops the rest of the queue. Right-click or empty-square click
  cancels the queue; viewing another position (history/analysis) also clears it. A selection or drag in progress survives the computer's move (`keepSelection`):
  its dots switch to real moves if it's now the player's turn, so premove chains aren't interrupted.
- Analysis: one variation at a time, branching from any main-line position; shown under the
  main-line row it replaces. Pauses vs-computer games; disabled mid-game with a clock.
- Draw offers in two-player games (moving instead of answering declines).
- Settings menu (gear): board colours, piece sets, think limit. Mute stays in the top bar.
- Piece sets in `wwwroot/pieces/<set>/` (each with its licence). CSS is generated by
  `tools/make-piece-css.py`; add the set to `Game/Settings.cs` too.
- Sounds: Kenney "Impact Sounds" (CC0), built by `tools/make-sounds.sh <folder with the .ogg files>`
  (the source pack is not kept in the repo).

### Session 3 additions
- **Pages** (Blazor routes): `/` Play (`Pages/Home.razor(.cs)`), `/arena`, `/games`, `/editor`.
  Shared header `Components/TopBar.razor` (page links + settings menu); `Layout/MainLayout.razor`
  wraps every page in `.app` with the theme/piece-set classes and `--anim` (piece slide time).
- **Services** (`Services/`, registered in `Program.cs`, one instance per visit):
  - `Prefs`: all settings (board, pieces, mute, volume, animation, hover hints, think limit), loads
    board.js once, sounds, clipboard, downloads. Raises `Changed`.
  - `AppState`: `Play` (the Play page's game, saved in `Home.DisposeAsync` and put back by
    `Restore`), `Review` (Games/Arena/Editor ask the Play page to open a game), `PlayFromFen`
    (editor → new-game dialog with `StartFen`), `EditorFen`, and the `ArenaSession`.
  - `GameHistory`: games as PGN in localStorage key `rlchess.history`, separated by U+001E,
    newest first, max 200. Extra PGN tags: Mode, Time, Id. Saved when a game ends
    (`Home.OnAfterRenderAsync`), when an unfinished game is replaced (`StartGame`), or a PGN is pasted.
  - `ArenaSession`: runs the website Arena. One async loop per board slot; slots take the next game
    number; fresh players per game; think limit = the settings' limit (over → loss). The page
    re-renders on a 100 ms timer when `Version` changes. Leaving the page pauses it (`PausedByLeaving`).
- Engine: `MatchStats` (wins/draws/losses, Elo ± margin, score interval, `ScoreChartSvg` used by the
  website and the console report), `TrainingData` (CSV), `ISearchStats` (optional node count),
  `Game.ToPgn(extraTags:)`, PGN Termination → end reason (our texts and lichess "Time forfeit").
- Console Arena: `--report`, `--export`, `bench` (`Bench.cs`, `Report.cs`).
- `ChessBoard`: hover hints (`HoverDests`, `OnHoverCallback`; JS reports mouse square changes) and
  `EditMode` (every piece draggable, drop off-board = -1). `MiniBoard`: view-only small board.
- Board textures: `tools/make-boards.py` generates `wwwroot/boards/{wood,marble}.jpg` from noise (no licences).
- Local testing of other pages: python's http.server doesn't serve 404.html for deep links, so
  navigate with the page links (GitHub Pages does serve 404.html, so deep links work live).

### Session 4 additions (brief "session 3")
- **Advanced menu**: Settings → Advanced (collapsible) with switches stored as `rlchess.adv.*`
  (`Prefs.ShowThinking/EvalBar/Review/OpeningNames/AnalysisSource`). All off by default; with all off,
  nothing extra renders or downloads (checked).
- **Thinking**: `SearchInfo` + `IReportsThinking` (engine/Players). Home sets `Report` in `RunBotTurn`
  (`StartThinking/StopThinking`), the 100 ms watcher redraws when the report changes. Arena
  `--thinking` (forces 1 thread) via `MatchRunner.PlayGame(onMove:)`; text by `ThinkingText`.
- **Gallery**: `PlayerPicker` is now cards + `BotAvatar` (generated hue from id, initials,
  category pattern). `Entry.Version`, `Entry.Spec(level)` ("id" or "id:level").
- **Versions**: `tools/freeze-bot.py <Name> <version>` copies `Players/Bots/<Name>` →
  `Players/Frozen/<Name>_<version>` renaming the namespace. Tested end to end in a scratch copy
  (freeze, register, build, rate).
- **Ratings**: `Ratings.Compute` (max-likelihood Elo, one virtual draw per pairing as a prior,
  anchor Random = 400). Arena `ratings` writes `wwwroot/ratings.json` (`RatingsFile`, JSON via
  Utf8JsonWriter/JsonDocument: trimming-safe). Website loads it with `BotRatings`. The committed file
  only has Random (400) until the owner has bots.
- **Analysis**: `IAnalysisEngine` (engine) with `PlayerAnalysis` (a bot that reports a Score) and
  `Services/StockfishEngine` (UCI over `wwwroot/js/engine.js`: a blob worker that `importScripts`
  stockfish-19-lite-single.js from jsDelivr, wasm URL passed after `#`). One analysis at a time
  (SemaphoreSlim); cancel = `stop` then wait for `bestmove`. `Services/Analysis` picks the source.
  The sandbox can't reach jsDelivr: local/live tests serve the identical npm files via Playwright
  `page.route` (files in the scratchpad `sf/`, downloaded from unpkg).
- **Eval bar**: `Components/EvalBar.razor`; Home's `MaybeStartEval` (after each render) analyses the
  shown position if it changed; uses the review's evals when a review covers the position.
- **Review**: `MoveReview` (labels, accuracy, `IsSacrifice`), `GameReviewer` (Services), UI in
  Home (`ReviewPanel`, badges in `MoveCell`, `ChessBoard.BadgeSquare/BadgeLabel`, `EvalGraph`).
  Reviews cached per game in `Analysis.Reviews`. Offered when the game is over or was opened from
  Games/Arena/PGN/editor.
- **Openings**: `OpeningBook` (engine); `wwwroot/openings.tsv` built by Arena `openings` from lichess's
  a–e.tsv (CC0). Loaded lazily by `Services/Openings`.
- Fixed: the new-game dialog's "Starting from your set-up position" note showed every time
  (a string parameter was passed without `@`, so it got the literal text).

### Session 5: Stockfish as a calibrated reference opponent
- The owner's bots: `Players/Bots/{Greedy,Minimax}`, frozen `Greedy_v1/v2`, `Minimax_v1`. **Don't edit them.**
- `PlayerCategory.Reference` with registry entries `stockfish` (levels = UCI_Elo 1320–3190, step 10,
  `LevelRange.Word = "Elo"`) and `stockfish-skill` (Skill Level 0–20, uncalibrated).
  `PlayerRegistry.StockfishFactory` is set by each host (console: `StockfishProcess.Register`, web:
  `Program.cs` → `WebStockfishPlayer`). `PlayerRegistry.OwnBots` excludes Reference (used by `ratings`
  default and the "Analysis by" list). `Entry.KnownRating(level)` = the Elo for calibrated Stockfish.
- Engine: `StockfishStrength` (UCI setup commands, `go movetime`, bestmove parsing), `RatingEstimate`
  (max-likelihood performance vs known ratings, half a draw prior, ± 95%, `OffTheScale` flag),
  `Ratings.Compute(..., fixedRatings)` for several anchors.
- Console: `StockfishProcess` (one process per player object, Threads=1, reports thinking),
  `Shared.TakeStockfishOptions` (`--stockfish-path`, `--sf-time`, any command), `strength` command,
  `ratings --stockfish 1320,1500` (Stockfish levels become the fixed anchors; Random floats). Main match
  prints an estimated rating when one side is calibrated Stockfish. Missing Stockfish → install help.
- Web: `StockfishEngine.PlayAsync` (set strength each move, `go movetime 1000`), `StockfishPool`
  (2 workers shared by all Stockfish players), Arena page shows `ArenaSession.StrengthEstimate`.
- Tests: `StockfishTests.cs`; the real-engine test uses `[StockfishInstalledFact]` (skipped if not
  installed; CI doesn't install it). Sandbox: `apt-get install stockfish` works (Stockfish 16).

## Decisions / gotchas
- Work straight on `main`; only push green builds.
- Licences: repo MIT. Pieces: Cburnett (BSD option, verified on Commons), Fantasy/Spatial
  (Maurizio Monge, MIT, verified in his repo; we use the configured copies lichess publishes),
  Chessnut (Alexis Luengas, Apache 2.0, licence text shipped in its folder). Sounds: Kenney CC0
  (licence text verified; files from a public mirror since kenney.nl blocks scripted downloads).
- Blazor shows its red error bar for anything written to stderr: log with `Console.WriteLine`.
- The website is single-threaded WebAssembly: a slow sync player freezes the page until it
  returns. `IAsyncPlayer` + `await Task.Yield()` keeps it responsive and stoppable.
- En passant square is only stored when a capture is possible (keeps repetition hashing right).
- Local test of the published site: publish, copy `wwwroot` into a folder named `rlChess`, set the
  base href to `/rlChess/`, serve the parent folder.
- The SDK isn't preinstalled in the cloud container: `dotnet-install.sh --channel 10.0`.
- Browser tests are ad-hoc Playwright scripts (not in the repo). Worth adding a small bUnit or
  Playwright suite if the UI keeps growing.
